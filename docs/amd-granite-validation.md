# Granite Ridge / 9950X3D 本轮还原与验证

2026-11-08，继续使用 REA 6.7.0、REA.SKILL 和 Ghidra 12.1.4，三个子代理
分别推进协议、字段与映射，并交叉审查核心、GUI、CLI 和分析输入。
参考固件为 ASUS ProArt X870E-CREATOR WIFI BIOS 2503 / SMU 98.84.0。
用户机器不在手边，实际 BIOS 未知；本轮没有 9950X3D 真机验收。

[验证提交 5055a86](https://github.com/SkyWalkerAMD/Instrumentum-Superfrequentationis/commit/5055a864cd8ab68683325117a9722cb037f570c4)
统一用于核心、GUI、CLI、安装包及 REA 完整验证。最终发布提交只更新文档和
验证记录，不改变已验证程序。八项既有用户扩展在本地目录单独保留。

## 本轮新增

| 功能 | GUI 与 CLI 共用实现 | 已验证范围 |
|---|---|---|
| Curve Shaper 保存偏移写入 | 一次修改一个档位的三个计数；全部旧计数须在 −50..30；两次新读取匹配完整旧表和能力字；发送一次设置后回读五个字 | 全部保存偏移匹配；不代表下游已应用、隐藏基线已知或硬件稳定 |
| 相同值与失败处理 | 相同值不发设置；拒绝过期、格式错误或越界旧表；识别未选档位改变、应答丢失和部分回读 | 保留“已尝试／已应答／保存表已核对”区别，不自动重试或回滚 |
| 固件核心状态记录 | GUI 导入、CLI `amd-core-status-decode --file capture.hob`；严格解码 528 字节 GUID HOB | 原始分配器将 524 字节请求按八字节对齐；500 字节有效载荷之后的四字节填充不参与解码；两个目标的禁用、启用掩码和三种状态，缺席目标单独标注，失败清空结果，全程离线 |
| 新协议与单位研究 | 双通道自动策略、手动覆盖边界、模型汇总的独立输入链 | 排除误解，尚未新增物理单位、物理映射或第二 rails 写入能力 |

Curve Shaper 读取继续保留完整 signed8 −128..127，越界数据可读但不能准备写入。
写入要求精确 Granite CPU/PCI 身份、非虚拟机、SMU 98.84.0、PBO 可用及手动
OC 关闭。固件会转发全部五个档位；保存表回读不是电气效果验证，外部软件仍可能
与检查竞争。详见[操作接口](amd-granite-controls.md)和[写入证据](amd-granite-shaper-write.md)。

## REA 与原始指令证据

云端重新执行 **46 组**固件证明，全部与本地结果一致。其中 42 组沿用源码未变的
既有本地结果，4 组为本轮新增本地回放；不把沿用结果称为本轮重新运行。

- [Shaper 写入](amd-granite-shaper-write.md)：73,073 例，包含完整保存表、
  所有字节组合、六包转发、应答失败、停滞与外部竞争。
- [核心状态生成与消费](amd-granite-map-binding.md)：5,384 例生成、5,380 例
  消费、8,256 例门检查，以及 13 个原始分配器边界场景；证明禁用与启用掩码相互独立。只保留低八位，不能替代
  SMU 映射器所需的低十六位，两个 bit 8 标志也不能替代 SMT bit 10。
- [rails 自动策略](amd-granite-rail-policy.md)：2,121 例。自动限幅不约束
  手动覆盖，不能据此开放未知写入或宣称设备回读。
- [模型校准边界](amd-granite-unit-calibration.md)：1,368 例。三路 SVI 功率
  与核心／CCD 模型进入不同汇总值；共享加项没有提供绝对单位校准。

REA 实际分析十个 UEFI 模块，包括新增的三份 IA32 TE 模块。原 TE 保持原样，
原字节回放仍直接读取它们；REA 使用单独散列的分析用 PE32 包装。
[转换验证](amd-granite-te-analysis.md)的十三组测试与独立审查核对九个节、
81,664 字节和十五处入口，实际 REA 返回的函数入口必须匹配原始 ImageBase + RVA。
这不是原 PE 文件恢复，也不是可安装的固件。所有合成服务边界和未模拟部分均明确保留。

冻结源码后另保留四项本地研究，不计入云端 46 项：共享加项来源的 3,359 例回放，
以及 rails 的 1,536 对编码别名反例（3,072 次原字节调用，另有两个组合路径和三个
不发送场景）。不同代码可以生成相同发送字而留下不同软件镜像，因此不能把镜像当作
独立设备回读。共享加项的查表、寄存器缩放和多项式来源也未提供绝对单位锚点。
另有 8 个 APOB 描述符发布样例，仍未建立状态 HOB 与核心身份的连接；相同状态
GUID 出现在不同 CPU 门控的模块中，也不能认证来源。310 组 Shaper 缓存实验进一步
覆盖节点合并、两温区端点／差值及下游插值，完整缓存部分使用 40 组模型输入；
寄存器窗口 ABI、fuse 服务和精确倒数仍为替代输入，完整求值不涵盖 n=0/1，
不证明真实锚点、基线内容或硬件应用。
脚本、结果及散列保留在本地 `build/granite24-*`，验证 JSON 明确标记为本地补充；
这些实验不增加已还原单位或已开放写入数，也不属于安装包的云端验收范围。

Linux 目标：el7, el8, el9, el10, ubuntu20.04, ubuntu22.04, ubuntu24.04, ubuntu26.04, debian11, debian12, debian13。EL7、EL8 的构建基线也通过相同 Qt 测试。
每个 Linux 目标收集 161 张截图，共 1,771 张；人工实图检查 EL7、EL10 和 Ubuntu
24.04 的新增 Shaper 写后结果与核心状态视图。截图来自合成数据，不是真机采集。
ASan/UBSan 覆盖十个核心测试，包含新增记录解析和 Shaper 写入。

首轮 Windows 的 Shaper 测试在 240.01 秒达到 CTest 上限。新写入／错误场景保留
每次真实 2 ms 传输等待，Windows／macOS 的计时粒度让总运行时间显著增加。
仅把这一个测试程序的总时限改为 600 秒后，四个平台重新通过完整核心验证。
没有缩短产品等待、减少测试场景或放宽断言，原失败日志保留在验证报告中。

首轮 HOB 回放曾用替代分配器把 524 字节请求误作记录长度。后续执行同一 BIOS 的
原始 PEI 分配器，证实实际长度为 528、最后四字节未初始化，随后修正共享解析器、
GUI、CLI、样例和负例，并以统一提交重跑全部任务；旧运行记录保留为已替代历史。

最终云端分析测试共 155 项，152 项通过、3 项需原始 TE 输入的集成测试在此跳过；
这三项在 REA 专项提供原始固件后全部通过，十三组转换测试无跳过。移植测试 34 项
通过。本地较早的 142 项原有分析全套中，
既有 Intel TVB 一秒模拟时限出现一次超时；代码不变的隔离复测两项通过，云端全套
也通过，原失败日志保留。其余本地跳过项目由云端工具链覆盖。本地用户目录
50 项移植测试，37 项通过，13 项因本机缺工具链跳过。

CLI 独立复核逐目标检查日志、冻结源码、安装／重装结果和产物散列。夹具逐条 JSON
未保存在产物中，因此独立审查不宣称重新执行了 1,742 个 payload。

入口。9950X3D 实际硬件的稳定性与效果仍待验证。
