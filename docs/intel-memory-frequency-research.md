# Intel 内存频率：后续还原依据

2026-10-12，本记录属于扩展时序交付后的研究文档，不代表已新增频率读取功能。

## 已确认

| 寄存器 | 偏移 / 位宽 | 手册含义 |
| --- | --- | --- |
| MC_BIOS_REQ | MCHBAR + 5E00h / 32 bit | BIOS 发出的内存控制器频率请求；31 位为 RUN/BUSY |
| MC_BIOS_DATA | MCHBAR + 5E04h / 32 bit | 反映最后一次 MRC 频率请求；MRC 结束后不代表当前内存频率 |
| BCLK_FREQ | MCHBAR + 5F60h / 64 bit | 低 32 位报告 BCLK，单位 kHz；高 32 位保留 |

§3.3.43（203 页）明确限制了 MC_BIOS_DATA 的时间语义。即使连续两次读到相同值，
也只能证明捕获时寄存器未变化，不能把它升级为当前频率测量。
§3.3.42–43（203–204 页）将请求编码分为 Gear[13:12]、参考时钟[11:8]、
QCLK 比率[7:0]；Gear 编码 0/1/2 分别表示 1/2/4，参考时钟 0/1 为
133.33/100 MHz 步进，QCLK 比率 0 表示 PLL 关闭、1–2 保留、3–255 才是比率。
不能沿用旧平台 DCLK ratio / odd ratio 的解释方式。

§3.3.51（209–210 页）说明 BCLK 是报告值，但这并未使“当前 BCLK × 历史请求比率”
成为实时内存频率。上述寄存器位于共享 PCU 区域，不能直接套用当前时序区的
MC +10000h / channel +0800h 地址规则。

## 后续实现边界

可继续研究独立的 BCLK 报告与“最后一次 MRC 请求”信息，分别保留来源、时间语义、
原始字和未知值。实时内存频率仍需找到运行时状态的正式定义，或其它可确认的测量来源。
这不是新增写入接口的依据，也不授权写入 MC_BIOS_REQ。
当前 14 寄存器 / 43 字段的 v2 快照不包含这些寄存器，仍按字段显示 tCK、QCLK、MC_DCLK，
不输出据此推算的 MHz、MT/s 或 ns。
