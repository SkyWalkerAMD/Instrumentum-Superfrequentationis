# AMD PM 遥测与快照：验证交付

生产提交 `62e7bd8272205ec15fe7ad23f223e122a3e039b2`，研究分支 `refactor/platform-recovery`。
[完整证据](validation/amd-pm-ci-62e7bd8.json)绑定源码、任务、日志、截图、安装包及其校验值。
[实现说明](amd-pm-recovery.md)记录字段单位、驱动依赖、输入约束与样本局限。

GUI / CLI 同步完成八个精确 Shimada 表版本的 24 项公共字段：FCLK/UCLK/MCLK、
五项电压，以及四条 SVI3 电源轨各四项读数；其中两项名称引用同一原始字，共 22 个偏移。
JSON 与原始表离线导入不访问硬件，显示值从原始字节重算。
已有兼容 ryzen_smu 驱动时可显式读表；版本/长度先核对，读完再次确认，失败不显示旧样本。
默认保留存储时钟，外部 BCLK 修正单独显示。非有限字段报错并保留其余有效数据。

Qt 新增快照互通、字段单位、部分坏数据、输入校验、驱动故障、异步窗口关闭等五项回归。
首次截图发现空表的修正时钟列标题截断；最终提交修复初始列宽，并增加宽度断言。
GUI、CLI 和共同核心均按最终提交重新验证，未用前一提交的截图代替。
CLI 测试另使用临时 sysfs 目录检验 4/8 字节长度字段、FIFO 和超长表拒绝；
真实主机没有该驱动节点时才测试缺失路径，不在 CI 触发未知真实固件访问。
驱动每个读取阶段失败、版本变化及未知版本等由独立合成后端覆盖。

十个 CLI 包均在无桌面、无 Qt、无构建工具的独立环境中完成安装、普通用户启动、卸载和重装。
归档 470 张界面截图；实际查看的子集与观察结论见证据清单，不能据截图认定真机读数正确。
交付文档更新前，32 个本轮文件已同步原目录：26 个换行规范化后与生产提交相同；六份既有文档仅应用功能变更，
保留用户目录独立历史及 UMC 引用。运行时、测试和构建代码全部匹配生产提交。
本轮未修改硬件驱动/HAL/ABI；重新验证原有内核装载及权限边界。
