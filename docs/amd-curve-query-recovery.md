# AMD 曲线查询还原

本轮在先前静态记录基础上加入了原指令合成执行、限定平台查询核心和界面。
本轮 `06b477c` 的[云端与产物证据](validation/amd-curve-recovery-ci-06b477c.json)已完成：核心 4/4、Linux 23/23，20 个安装包。

## 新实现范围

`gui/core/amd_curve.cpp` 使用独立 B8/BC 通道，限定 `AuthenticAMD` family `1Ah`、
PCI `1022:153a`、domain 0 / BDF 0。每次请求重新识别目标。
界面手动输入固件 CCD 0–15 / core 0–7，不从 Linux CPU 或 CPUID 拓扑自动推导。
这些是允许编码的范围，不能证明具体物理核心存在或映射正确。

查询只发送 `a3`，参数区 `3b10a40`；先等待非零旧响应，再清响应、提交目标和查询。
成功必须得到本次 response 1 并成功读取返回参数。结果保留原始 32 位值，
显示十六进制与有符号十进制，不换算为 mV，不设置曲线。
每次等待最多 100 次轮询，并受事务期限和取消控制。
任何身份不匹配、访问错误、固件拒绝、超时或取消都不发布数值；界面清除旧结果。
不重试，不执行通用 MP1 的 `0x50200=1` 写入，也不复现原程序的 TSC/端口锁。
进程内整个事务使用现有服务互斥锁，不能保证其它进程/内核驱动不会同时访问。

## 原指令实验

[固定片段](../analysis/fixtures/legacy-amd-curve-query.json)包含完整构造和 `get_co` 两个函数，
SHA-256 为 `b9697d32e80989e79ff0e9c7376759682d545bf97ca1495483909671d76f9b18`。
[指令审计](validation/legacy-amd-curve-query-instructions.json)和[本机实验](validation/legacy-amd-curve-query-local.json)
记录 98 组构造、71 组查询。PCI 设备发现、读写包装、延迟与互斥锁都是显式替身，
没有执行真实寄存器访问或完整原程序启动。

实验确认 Shimada 覆盖会更改 response/command/query，却保留先前 mobile/GPT 路径的 argument 地址；
因此不能仅凭最后一个 Shimada 标志无条件选择 `3b10a40`。
本次只纳入原 BDF0 `153a` 身份对应的非 mobile/GPT 路径，排除其它设备与混合历史标志。
原查询忽略对象保存的设备字段，仍访问 BDF0；core 截为八位，CCD 左移会回绕。
原固件错误/忙状态轮询十次后仍返回参数，读失败的 `ffffffff` 也直接作为整数返回。
新实现不会把这类结果标记为有效。

新增 7 组 C++ 核心场景覆盖资格限制、原始值/边界编码、每个访问失败位置、固件状态、
有界等待、各阶段取消、截止时间与每次身份重查。3 项 Qt 回归覆盖输入、返回值、目标改变和失效清理。
4 项原指令回归和完整构造/查询实验加入云端门禁。

## 前一轮静态记录

本页是本轮 Intel 倍频生产提交 `fa39af6` 之后的静态研究，不属于该提交的运行时新增功能或云端场景计数。
没有启用曲线设置，也没有执行原程序硬件指令。

[固定 ELF 证据](validation/legacy-amd-curve-query-static.json)包含三个完整函数：
`AMD_PBO` 构造（0x239150）、`get_co(int,int)`（0x239bc0）和六字段页面的 curve Apply 槽（0x750b70）。

在 Shimada 标志非零、未先命中 mobile/GPT 改写参数地址的构造路径中，
成员 +4/+8/+c 分别为 response `3b10970`、command `3b10924`、argument `3b10a40`；
查询命令成员 +20 为 `a3`。它使用 B8/BC 间接 PCI 对，与现有 F8/FC BIOS SMUIO 独立。

`get_co` 把第一个参数左移 28 位，第二个参数截成 8 位再左移 20 位，合并后提交给固件。
原函数硬编码 PCI BDF 0，不能把构造对象中的设备字段误认为此调用已经使用的 BDF。
第二参数可以越过通常的 core 位范围；重构时需要确认并收紧目标编码，而非照抄截断。

该函数体没有 MP1 通用入口的 `0x50200=1` 写入，但这不证明原启动过程不依赖其它初始化。
清 response、写 argument、发命令后，原循环最多读取 response 十次；即使没有得到 1 也继续读取 argument。
界面将返回值直接作为有符号 32 位十进制输出，因此错误或旧数据可能被展示为有效曲线值。
尚不能由这个显示方式推导 CO step 的物理电压单位。

上述构造与查询合成执行及独立有界查询已在本轮源码实现。
CPUID 的 CCD/core 编号到固件编号的关系仍未证明，当前拓扑读取不会自动填充或触发曲线查询。
固件的真实返回语义、初始化依赖、物理核心映射与目标机器验收仍未完成；曲线设置仍未恢复。
