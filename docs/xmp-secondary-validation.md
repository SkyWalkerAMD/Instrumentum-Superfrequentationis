# DDR5 XMP 次级时序：GUI 与 CLI 同步验证

生产提交 `84f21bc98fb03fd05b5fd23e9d9e44303eb5fa13`，研究分支 `refactor/platform-recovery`。
[证据清单](validation/xmp-secondary-ci-84f21bc.json)绑定同一提交的云端运行、日志、安装包、源码和 SHA256。
[字段与使用说明](ddr5-xmp-recovery.md)和[固定来源](validation/xmp-secondary-sources.json)记录格式依据及限制。

三组有效厂家档案各新增 8 项次级时序及其独立周期下限，数值从 14 项扩展到 30 项。
时间为 ps，周期下限为 nCK；不推导当前训练值，不把零或最大编码解释为 Auto 或有效硬件设置。
既有 CRC、版本、启用位、截断和 EXPO 重叠检查继续生效；DDR4 和 EXPO 基础档案范围不变。

新增四组 SPD 核心场景，覆盖三档案字段名称/单位、24 个字段字节全部 256 编码、
邻接字段与不同档案隔离、零/最大编码、校验失败及禁用档案。
改变 tCK 或使用时间值与周期下限不相称的编码时，程序仍保留两个独立存储值。
单独检查 tCCD_L_WR 与 tCCD_L，避免上游推导 getter 的字段混用。

CLI 新增五份离线报告，共 34 份 SPD 报告；打开前拒绝的 132 个命令仍通过。
新场景确认全过程不创建硬件后端。GUI 对三组全部新增字段检查名称、数值和单位，
并验证零值、损坏/禁用档案和加载短文件后清除旧行。保存 360 张截图，查看范围见证据清单。
十目标 CLI 在无显示、无 Qt、无构建工具的镜像中完成安装、普通用户运行、卸载和重装。

公开独立 XMP 档案提供了第一组非零次级值，合成模块复用这些格式事实；
其余槽位加入独立标记用于测试，不能作为推荐配置。既有混合样本的次级字段均为零。
所有这些检查均不构成目标主板 EEPROM 采集、内存训练或稳定性验收。
