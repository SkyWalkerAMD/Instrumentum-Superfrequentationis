# DDR4 XMP 2.0：GUI 与 CLI 同步验证

生产提交 `b1b9adf96b33f8f3050a5497dfab116dbafb7f49`，研究分支 `refactor/platform-recovery`。
[证据清单](validation/ddr4-xmp-ci-b1b9adf.json)绑定同一提交的运行、日志、安装包、源码和 SHA256。
[实现与边界](ddr4-xmp-recovery.md)记录固定格式来源、字段定义和错误隔离。

两端同步读取 DDR4 两组 XMP 2.0 档案，各含 VDD 和 12 项存储时序。
独立处理启用位、时间基准、截断、未知版本和有符号修正；一组失败仍保留另一组有效结果。
XMP 2.0 无扩展 CRC，基础 SPD CRC 不覆盖档案，界面和 JSON 均不声称其校验通过。
这是基于公开字段定义的内存功能扩展，未执行原版 ELF 的 DDR4 XMP 函数。

| 验证层 | 结果 |
|---|---|
| [共同核心](https://github.com/SkyWalkerAMD/Instrumentum-Superfrequentationis/actions/runs/38099021180) | 4/4：Ubuntu 22.04/24.04、Windows 2022、macOS 14；各 12 CTest、122 场景组 |
| ASan / UBSan | Ubuntu 24.04 的 SPD 解码、UMC 解析/比较通过 |
| [独立 CLI](https://github.com/SkyWalkerAMD/Instrumentum-Superfrequentationis/actions/runs/38099021189) | 12/12；十目标各 14 CTest、15 组命令场景、132 个打开前拒绝、288 份 JSON 报告 |
| [Linux GUI / 驱动](https://github.com/SkyWalkerAMD/Instrumentum-Superfrequentationis/actions/runs/38099021214) | 23/23；十目标与 EL8 基线各 61 Qt 测试；11 套内核 VM |
| 既有原指令 / 分析回归 | 74 项云端分析测试通过；未计入新的原 DDR4 XMP 指令执行 |
| 原目录本机检查 | 48 项：36 通过、12 缺工具链/环境跳过；文档链接、确定性源码归档和回读通过 |

SPD 核心共 17 组场景，其中 6 组新增 DDR4 覆盖：两组数值/单位、0..512 全部捕获长度、
全部配置与时间基准字节、七项有符号修正的全部 256 编码、电压编码、组合字段边界、
基础 CRC 失败和 DDR4/DDR5 类型隔离。tRC fine 修正不会错误加给 tRAS。
改变 XMP 数据不会影响基础 CRC，回归明确确认这一完整性限制。

CLI 新增十份离线报告，共 29 份 SPD 报告；验证空值、无 CRC/无名称语义、
两档独立错误、禁用残留及全过程不创建硬件后端。旧 DDR5 XMP/EXPO 场景仍通过。
GUI 新增复合回归：两档数值和单位、无校验标签、独立时间基准错误、第二档独立启用、
截断后清除旧数值，并确认 DDR4 不显示 EXPO 或虚构档案名称。

十目标 CLI 在无显示服务、无 Qt、无构建工具的环境中完成安装、普通用户运行、卸载和重装。
保存 350 张截图；本轮查看的 DDR4 档案窗口及内存页范围见证据清单。
夹具均为合成数据，不是实机稳定性验收。

## 交付

`dist/gui-cli-ddr4-xmp-b1b9adf/`：十目标各 GUI、CLI、可选 DKMS，共 30 个 Linux x86_64 包，
另附源码、源码 SHA256 侧车与 SHA256SUMS，共 33 个文件。
版本仍为研究版 2.0.1，以提交目录和校验值区分构建。
安装包和源码固定于生产提交；本验证报告及索引属于随后单独提交的交付记录。

- GUI 包：10,492,814–14,286,398 字节；CLI 包：209,448–260,890 字节，不含可选驱动或系统运行库。

- 18 个变更文件在原目录、云端工作树和源码归档间一致（规范化换行）。
- 其它 NVL 研究、打包改动和历史 UMC 文档差异保留；驱动/HAL/ABI 未改动。
